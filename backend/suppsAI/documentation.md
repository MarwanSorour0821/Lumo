# suppsAI API Documentation (Phase 2: deterministic scheduler)

## Endpoint: POST /api/suppsai/schedule/

**Description:**
Returns a supplement schedule for the authenticated user, based on their saved supplements. Uses the supplements knowledge base + deterministic scheduler (no OpenAI). Requires an active subscription.

**Request:**
- Method: POST
- Auth: Required (Bearer token)
- Body: (none required; uses user's supplements from DB)

**Response:**
- 200 OK: `{ "schedule": { "Magnesium": "21:00", "Vitamin D3": "08:00", ... }, "unknown": [] }`
- 403: `{ "error": "Subscription required." }`
- 400: `{ "error": "No supplements found." }`

**Logic:**
- Fetches supplement names from `food_supplement_items` for the user.
- Calls `build_schedule(names)` in `suppsAI/scheduler.py`, which uses `supplements` app lookup and assigns each supplement to a time slot (morning 08:00, midday 12:00, afternoon 15:00, evening 18:00, before_bed 21:00) respecting `best_times` and `dont_take_with`.
- Returns schedule (input name -> time) and list of names not found in the knowledge base (`unknown`).

## Test endpoint: POST /api/suppsai/schedule/test/

**Description:**
Same scheduler logic, but accepts a list of names in the body (no auth). Use only for testing Phase 2.

**Request:**
- Method: POST
- Auth: None
- Body: `{ "names": ["Magnesium", "Vitamin D3", "Iron", "Calcium"] }`

**Response:**
- 200 OK: `{ "schedule": { "Magnesium": "21:00", "Vitamin D3": "08:00", "Iron": "08:00", "Calcium": "18:00" }, "unknown": [] }`

---

## Implementation Notes
- Schedule is generated by `suppsAI/scheduler.py` using `supplements` app (Phase 1 lookup).
- Only users with valid subscriptions can use the main schedule endpoint.
- The schedule can be used to set reminder times in the app (Phase 3).
